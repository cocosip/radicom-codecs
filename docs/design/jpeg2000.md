# Classic JPEG 2000 codec design

This document is the planned implementation contract for the
`radicom-codecs-jpeg2000` crate. It covers DICOM JPEG 2000 raw codestreams,
not JP2/JPT wrappers or HTJ2K. The same crate also owns the HTJ2K modules;
HTJ2K changes the code-block coder while sharing the JPEG 2000 container,
wavelet, packet, and DICOM adapter layers.

## Standards and reference

- ISO/IEC 15444-1 / ITU-T T.800, JPEG 2000 core coding system.
- DICOM PS3.3 and PS3.5, Image Pixel Module and JPEG 2000 transfer syntaxes.
- `fo-dicom.Codecs DicomJpeg2000Codec.cs` is a behavior reference.
- OpenJPEG output and fo-dicom acceptance tests may be used as external test
  oracles only. Their source is not copied, vendored, linked, or called by the
  Rust implementation.

## Registrations

| Type | UID | Coding mode | Status target |
| --- | --- | --- | --- |
| `Jpeg2000LosslessCodec` | `1.2.840.10008.1.2.4.90` | reversible 5/3, exact | encode/decode |
| `Jpeg2000LossyCodec` | `1.2.840.10008.1.2.4.91` | irreversible 9/7, quantized | encode/decode |

Both implement `radicom::pixel::codec::Codec` and accept only
`CodecParams::Jpeg2000(J2kParams)`. `.90` forces reversible mode and `.91`
forces irreversible mode; a mismatched parameter is an error before frames are
read.

## Supported DICOM contract

The adapter accepts non-zero dimensions, 8/16 `BitsAllocated`, valid
`BitsStored`, one or three components, unsigned or signed samples, and
MONOCHROME1/2 or RGB. Planar RGB is normalized to interleaved samples and
repacked after decode when requested. YBR_FULL and YBR_FULL_422 are converted
to full-range RGB before coding, matching fo-dicom. Partial YBR, palette,
CMYK, unknown photometric values, JP2 boxes, JPIP, and Part 2 extensions are
rejected explicitly.

Raw J2K frames are encapsulated one frame per codestream. DICOM padding belongs
to `PixelData::add_frame`; it is never passed to the codestream parser. Before
decoding, SIZ width/height/component count/precision/signedness and the checked
decoded byte count must fit the declared destination buffer. This prevents the
geometry and integer-overflow failures covered by fo-dicom's
`Jpeg2000GeometryUnitTest`.

## Codec pipeline

The planned crate keeps the shared layers in one implementation. `common.rs`
defines the frame contract, `codestream.rs` owns DICOM sample packing, and the
classic and HTJ2K modules select their Tier-1 code-block coder. No `vendor/`
directory or external JPEG 2000 engine is part of this design.

The shared codestream layer parses and writes SOC/SIZ/COD/COC/QCD/QCC/POC/TLM/
SOT/SOD/EOC, derives tile/component/resolution geometry, and assembles packets.
The classic path then performs:

1. reversible 5/3 or irreversible 9/7 wavelet transform;
2. reversible or scalar irreversible quantization;
3. EBCOT significance-propagation, magnitude-refinement, and cleanup passes;
4. MQ arithmetic coding for every code-block segment;
5. Tier-2 tag-tree packet headers and the selected progression order.

The encoder may use one-tile LRCP as its initial default, but the decoder must
not assume that profile. It must either handle valid tile-parts, precincts,
progression changes, and optional marker segments or reject each unsupported
profile explicitly before decoding. Marker lengths, packet bounds, code-block
sizes, bit counts, and allocations are checked; truncated SOD, missing EOC,
duplicate required markers, inconsistent component geometry, and trailing
non-padding bytes fail with `Error::Codec`.

## Parameters and metadata

`J2kParams::rate` is a project encoding policy for the target compression
ratio; DICOM and ISO/IEC 15444-1 do not define that field. `rate_levels` adds
quality layers in descending target order. `allow_mct` enables RCT for lossless
RGB or ICT for lossy RGB. `update_photometric_interpretation` records a color
transform in the destination metadata; `encode_signed_as_unsigned` requests an
explicit signed-to-unsigned coding mapping and is never applied implicitly.

The decoded codestream must agree with DICOM geometry. If ICT/RCT metadata is
present, the adapter exposes RGB when the update flag is enabled. Lossless
paths compare samples exactly after native byte order and planar repacking;
lossy paths use bounds tied to an explicit project quality profile; they are not
presented as ISO or DICOM requirements.

## Stages and checks

1. Marker/bit/geometry primitives and malformed-header tests.
2. 5/3, MQ, EBCOT, tag trees, packet assembly, and exact `.90` round trips.
3. 9/7, quantization, quality layers, and `.91` tolerance tests.
4. DICOM frame/color adapter, multi-frame/padding/planar/signed tests.
5. Fo-dicom bidirectional fixtures, geometry-overrun regressions, marker/profile
   matrix tests, and bounded fuzz/property tests.

The implementation target is pure Rust with no native, FFI, vendored, or
third-party JPEG 2000 runtime dependency. HTJ2K remains in this same crate and
uses the shared contract until its Part 15 block coder is implemented.
