# Classic JPEG 2000 codec design

This document is the implementation contract for the
`radicom-codecs-jpeg2000` crate. It covers DICOM JPEG 2000 raw codestreams,
not JP2/JPT wrappers or HTJ2K. The same crate also owns the HTJ2K modules;
HTJ2K changes the code-block coder while sharing the JPEG 2000 container,
wavelet, packet, and DICOM adapter layers.

## Standards and reference

- ISO/IEC 15444-1 / ITU-T T.800, JPEG 2000 core coding system.
- DICOM PS3.3 and PS3.5, Image Pixel Module and JPEG 2000 transfer syntaxes.
- `fo-dicom.Codecs DicomJpeg2000Codec.cs` is a behavior reference.
- OpenJPEG output and fo-dicom acceptance tests may be used as external test
  oracles only. Their source is not copied, vendored, linked, or called by the
  Rust implementation. Parts of the geometry, cleanup-pass and Annex C table
  code are ported from the pure C# `fo-dicom.PureCodecs` reference.

## Registrations

| Type | UID | Coding mode | Status |
| --- | --- | --- | --- |
| `Jpeg2000LosslessCodec` | `1.2.840.10008.1.2.4.90` | reversible 5/3, exact | encode/decode |
| `Jpeg2000LossyCodec` | `1.2.840.10008.1.2.4.91` | irreversible 9/7, quantized | encode/decode |

Both implement `radicom::pixel::codec::Codec` and accept only
`CodecParams::Jpeg2000(J2kParams)`. `.90` forces reversible output and rejects
`irreversible=true` when encoding. `.91` honors `irreversible=false` by writing
a reversible 5/3 codestream (QCD style 0), matching fo-dicom; the default
`irreversible=true` selects 9/7. Parameters are encoding policies only: decoding
accepts `J2kParams::default()` and ignores the mode fields.

## Supported DICOM contract

The adapter accepts non-zero dimensions, 8/16 `BitsAllocated`, valid
`BitsStored`, one or three components, unsigned or signed samples, and
MONOCHROME1/2 or RGB. Planar RGB is normalized to interleaved samples and
repacked after decode when requested. YBR_FULL and YBR_FULL_422 are converted
to full-range RGB before coding, matching fo-dicom. Partial YBR, palette,
CMYK, unknown photometric values, JP2 boxes, JPIP, and Part 2 extensions are
rejected explicitly.

Raw J2K frames are encapsulated one frame per codestream. DICOM padding belongs
to `PixelData::add_frame`; it is never passed to the codestream parser. Before
decoding, SIZ width/height/component count/precision/signedness and the checked
decoded byte count must fit the declared destination buffer. SIZ is validated
with checked `u64` arithmetic and a `1 << 28` sample limit over all components
before any component buffer is allocated, so a malformed 41-byte SIZ declaring
65535 x 65535 samples is rejected instead of aborting the process. This prevents
the geometry and integer-overflow failures covered by fo-dicom's
`Jpeg2000GeometryUnitTest`.

## Codec pipeline

The crate is organized as `bit`, `marker`, `geometry`, `wavelet`,
`quantization`, `mq`, `tier1`, `tier2`, `codestream`, `frame`, and `lib`.
`codestream` owns the container, `frame` owns DICOM sample packing, and
`tier1` owns the classic EBCOT code-block coder. No `vendor/` directory or
external JPEG 2000 engine is part of the implementation.

The codestream layer parses and writes SOC/SIZ/COD/COC/QCD/QCC/TLM/SOT/SOD/EOC,
derives tile/component/resolution/precinct/code-block geometry, and assembles
packets. The classic path performs:

1. reversible 5/3 or irreversible 9/7 wavelet transform;
2. reversible or scalar irreversible quantization;
3. EBCOT significance-propagation, magnitude-refinement, and cleanup passes;
4. MQ arithmetic coding for every code-block segment;
5. Tier-2 tag-tree packet headers in the selected progression order.

The encoder uses one tile, five decomposition levels, 64x64 code blocks,
`Scod=0` (default 15/15 precincts), one quality layer, LRCP progression, no
SOP/EPH/TLM, and code-block style 0. It writes reversible QCD style 0 for
reversible output and scalar-expounded style 2 for irreversible output. A
multiple component transform is applied only when `allow_mct` and
`update_photometric_interpretation` are both set and the image has three
components: reversible output uses RCT and is labelled `YBR_RCT`, irreversible
output uses ICT and is labelled `YBR_ICT`. With the default
`update_photometric_interpretation=false` the encoder stores RGB without MCT and
leaves the photometric interpretation unchanged, which is a valid profile and
avoids an unnecessary transform. The HTJ2K codec `default_params()` enables
`employ_color_transform` for fo-dicom/OpenJPH parity. In radicom 0.1.0 the bare
`HtJ2kParams::default()` still has it false; the accompanying core fix changes
that default to true, so until that release use `default_params()` (or set the
flag) when MCT is required. Enabled, it writes `YBR_RCT`/`YBR_ICT` as PS3.5
requires; disabled, RGB is stored without MCT and keeps the `RGB` label.

The decoder accepts multi-tile-part codestreams (parts are concatenated),
multiple quality layers (inclusion, zero-bit-plane and length state persists
across layers, and layer segments are prefixes of one continuous MQ stream),
QCD styles 0/1/2 (style 1 stores the band-0 record and derives every other
band's exponent with the A.6.4 resolution-level reduction, saturating at zero),
COC/QCC overrides from the main and tile-part headers (with the one-byte
component index mandated for fewer than 257 components), and the
LRCP/RLCP/RPCL/PCRL/CPRL progression orders. RPCL/PCRL/CPRL use precinct index
order, which is exact when a resolution has a single precinct (the DICOM
default). Multi-precinct codestreams decode with explicit precinct sizes.
`COD.MCT` is a flag: a nonzero value selects the multiple component transform,
and the wavelet transform chooses RCT for reversible streams and ICT for
irreversible ones. The decoder reverses the matching transform before packing
RGB; MCT with fewer than three components, or a `COD.MCT` value above 1, is
rejected.
Tile bounds may exceed the image as long as they describe a single tile; a tile
grid with more than one tile is still rejected. `Psot=0` is accepted only for
the final tile-part, and every declared tile-part must be consumed exactly. TLM
segments are accepted, their bounded lengths are validated, and the table itself
is ignored because there is no consumer for it. Classic decoders reject HTJ2K
codestreams (CAP present, `Rsiz & 0x4000`, or COD code-block style 0x40) with an
explicit error.

POC, PPM, PPT, PLM, RGN, CRG, component subsampling, multi-tile codestreams,
JP2 boxes, and Part 2 extensions are rejected explicitly. A COD `Scod` that
signals SOP or EPH markers is rejected as well, because the packet reader does
not parse start-of-packet/end-of-packet markers. Code-block styles BYPASS,
TERMALL, PTERM, and HT are rejected; RESET, VSC, and SEGSYM are handled (SEGSYM
codes signs of coefficients that become significant in the cleanup pass with the
uniform context, as T.800 requires). Per-component COC overrides are accepted
only when they keep the COD decomposition level count and code-block size.
Marker lengths, packet bounds, code-block sizes, bit counts, and allocations are
checked; truncated SOD, missing EOC, duplicate required markers, inconsistent
component geometry, and trailing non-padding bytes fail with `Error::Codec`. At
most one `0x00` padding byte is accepted after EOC.

The RESET/VSC/SEGSYM code-block styles each have a Tier-1 round-trip test, and
multi-precinct geometry and rejection paths have unit coverage; end-to-end
multi-precinct codestreams are not part of the current fo-dicom interop matrix
(which uses style 0 and one precinct per resolution).

## Parameters and metadata

`J2kParams::rate` is a project encoding policy for the target compression ratio
(uncompressed frame bytes over compressed frame bytes); DICOM and ISO/IEC
15444-1 do not define that field. The classic encoder emits a single quality
layer, so on the irreversible path it reaches `rate` by scaling the 9/7
quantization steps by `2^shift` and re-encoding until the codestream fits the
ratio. Each step drops whole bit-planes, so the achieved ratio overshoots the
target; `rate = 0` keeps the near-lossless default steps. `rate_levels` still
returns an explicit "not implemented" error because multiple quality layers are
not implemented. A reversible (`.90`, or `.91` with `irreversible=false`) encode
ignores `rate`, because quality layers do not apply to its 5/3 path. `allow_mct`
implements classic RCT/ICT
as described above, but only together with
`update_photometric_interpretation=true`; otherwise the encoder keeps the
existing RGB/no-MCT behavior. `update_photometric_interpretation` writes RGB (or
the MCT label) for three-component output when set, and leaves the source
photometric interpretation untouched when false; decoding still exposes RGB.
`encode_signed_as_unsigned` is not implemented and returns an explicit error on
encode rather than silently changing the sample domain; decoding ignores it.

The decoded codestream must agree with DICOM geometry. If the codestream uses
RCT/ICT, the adapter exposes RGB. Lossless paths compare samples exactly after
native byte order and planar repacking; lossy paths use bounds tied to the
project quality profile, not ISO or DICOM requirements.

The irreversible path follows OpenJPEG's coefficient convention exactly. The
QCD stores `1/norm` per subband, and both the encoder's quantization step and
the decoder's inverse-quantization step include the subband's 2-D gain
(`2^gain` = 1/2/2/4 for LL/HL/LH/HH, Equation E-4) because that is where the
reference implementations fold it. The synthesis filter itself uses the
standard `1/K` high-pass gain from Annex F.3. OpenJPEG's inverse transform uses
`2/K` instead (`two_invK` in `dwt.c`, a documented historical quirk compensated
by using `R_b = prec` in `tcd.c`); that pair differs from the standard by
exactly the subband gain. Pairing `1/K` synthesis with a gain-scaled step
reproduces OpenJPEG and OpenJPH samples; pairing `1/K` with an unscaled step is
wrong by a factor of two per detail direction, and an OpenJPEG-written `.91`
codestream decodes about 30 grey levels away from OpenJPEG's own output.

A codestream may carry a wider precision than the destination's `BitsStored`:
fo-dicom's OpenJPH encoder writes `BitsAllocated` (16) into SIZ for a 12-bit
dataset. The decoder therefore accepts any codestream precision between
`BitsStored` and `BitsAllocated` and re-centres unsigned samples on the
destination's level shift. Signed samples are not level shifted, so a wider
precision only acts as a container width and is range-checked instead. Lossless
codestreams refuse samples that do not fit `BitsStored`; for irreversible
(lossy) codestreams, reconstruction overshoot outside the destination range is
clamped, because ringing is expected there.

## Verification

- Unit tests cover bit stuffing, marker parsing, geometry, MQ, Tier-1 (including
  RESET, VSC, SEGSYM, and combined styles), tag trees, pass-count coding, 5/3
  and 9/7 transforms, quantization styles 0/1/2, codestream round trips
  (including custom precincts and RCT/ICT), sample-cap and Psot/EOC boundary
  rejection, HTJ2K rejection, and the DICOM frame adapter.
- Facade tests cover 8/16-bit, 12-bit-stored, signed, wider-precision signed,
  lossy clamping, RGB, planar RGB, MCT labelling, and multi-frame paths through
  `PixelData`.
- The registry/transcoder integration test covers `.90` exact transcoding,
  `.91` tolerance, RGB, multi-frame, and malformed-codestream rejection without
  a partial frame.
- An OpenJPEG-written irreversible codestream and the samples that release
  decodes back are embedded in a unit test, so the coefficient convention above
  cannot regress silently (it fails by 114 grey levels without the subband
  gain).
- The OpenJPEG 2.5.4 bidirectional matrix (`.interop/run-j2k-interop.ps1`
  driving `.interop/j2k-oracle`, git-ignored together with the downloaded
  binaries) passes after the correction: `.90` is byte-exact in both directions
  at 8 and 12 bits, an OpenJPEG `.91` decodes within `mean 0.002 / max 1` of
  OpenJPEG's own output at 8 bits (`0.036 / 1` at 12 bits), and an OpenJPEG
  decode of a Rust `.91` is within `mean 0.172 / max 2` of the Rust decode of the
  same codestream. The 12-bit cases store 12 bits in 16-bit words.
- The fo-dicom.Codecs 5.16.7 DICOM-level matrix (`.interop/dicomref`, C#) passes
  in both directions for `.90` and `.91` at 8 and 12 bits: a fo-dicom stream
  decodes exactly (`.90`) or within `max 1` (`.91`), and fo-dicom decodes a Rust
  stream within `max 2`.
- The optional pure-Rust `j2k_tool` example is a developer utility for manual
  codestream inspection; `--stored` separates `BitsStored` from
  `BitsAllocated` for 12-bit-in-16 frames.

## Stages and checks

1. Marker/bit/geometry primitives and malformed-header tests. (done)
2. 5/3, MQ, EBCOT, tag trees, packet assembly, and exact `.90` round trips. (done)
3. 9/7, quantization, multi-layer decoding, and `.91` tolerance tests. (done)
4. DICOM frame/color adapter, multi-frame/padding/planar/signed tests. (done)
5. OpenJPEG bidirectional matrix and the embedded OpenJPEG `.91` fixture. (done;
   the HTJ2K half still needs an OpenJPH or fo-dicom oracle, and broader
   fuzzing remains future work)

The implementation target is pure Rust with no native, FFI, vendored, or
third-party JPEG 2000 runtime dependency. HTJ2K remains in this same crate and
uses the shared contract until its Part 15 block coder is implemented.
