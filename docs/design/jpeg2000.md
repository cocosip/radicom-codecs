# Classic JPEG 2000 codec design

This document is the implementation contract for the
`radicom-codecs-jpeg2000` crate. It covers DICOM JPEG 2000 raw codestreams,
not JP2/JPT wrappers or HTJ2K. The same crate also owns the HTJ2K modules;
HTJ2K changes the code-block coder while sharing the JPEG 2000 container,
wavelet, packet, and DICOM adapter layers.

## Standards and reference

- ISO/IEC 15444-1 / ITU-T T.800, JPEG 2000 core coding system.
- DICOM PS3.3 and PS3.5, Image Pixel Module and JPEG 2000 transfer syntaxes.
- `fo-dicom.Codecs DicomJpeg2000Codec.cs` is a behavior reference.
- OpenJPEG output and fo-dicom acceptance tests may be used as external test
  oracles only. Their source is not copied, vendored, linked, or called by the
  Rust implementation. Parts of the geometry, cleanup-pass and Annex C table
  code are ported from the pure C# `fo-dicom.PureCodecs` reference.

## Registrations

| Type | UID | Coding mode | Status |
| --- | --- | --- | --- |
| `Jpeg2000LosslessCodec` | `1.2.840.10008.1.2.4.90` | reversible 5/3, exact | encode/decode |
| `Jpeg2000LossyCodec` | `1.2.840.10008.1.2.4.91` | irreversible 9/7, quantized | encode/decode |

Both implement `radicom::pixel::codec::Codec` and accept only
`CodecParams::Jpeg2000(J2kParams)`. `.90` forces reversible mode and `.91`
forces irreversible mode; a mismatched parameter is an error before frames are
read.

## Supported DICOM contract

The adapter accepts non-zero dimensions, 8/16 `BitsAllocated`, valid
`BitsStored`, one or three components, unsigned or signed samples, and
MONOCHROME1/2 or RGB. Planar RGB is normalized to interleaved samples and
repacked after decode when requested. YBR_FULL and YBR_FULL_422 are converted
to full-range RGB before coding, matching fo-dicom. Partial YBR, palette,
CMYK, unknown photometric values, JP2 boxes, JPIP, and Part 2 extensions are
rejected explicitly.

Raw J2K frames are encapsulated one frame per codestream. DICOM padding belongs
to `PixelData::add_frame`; it is never passed to the codestream parser. Before
decoding, SIZ width/height/component count/precision/signedness and the checked
decoded byte count must fit the declared destination buffer. This prevents the
geometry and integer-overflow failures covered by fo-dicom's
`Jpeg2000GeometryUnitTest`.

## Codec pipeline

The crate is organized as `bit`, `marker`, `geometry`, `wavelet`,
`quantization`, `mq`, `tier1`, `tier2`, `codestream`, `frame`, and `lib`.
`codestream` owns the container, `frame` owns DICOM sample packing, and
`tier1` owns the classic EBCOT code-block coder. No `vendor/` directory or
external JPEG 2000 engine is part of the implementation.

The codestream layer parses and writes SOC/SIZ/COD/COC/QCD/QCC/TLM/SOT/SOD/EOC,
derives tile/component/resolution/precinct/code-block geometry, and assembles
packets. The classic path performs:

1. reversible 5/3 or irreversible 9/7 wavelet transform;
2. reversible or scalar irreversible quantization;
3. EBCOT significance-propagation, magnitude-refinement, and cleanup passes;
4. MQ arithmetic coding for every code-block segment;
5. Tier-2 tag-tree packet headers in the selected progression order.

The encoder uses one tile, five decomposition levels, 64x64 code blocks,
`Scod=0` (default 15/15 precincts), one quality layer, LRCP progression, no
SOP/EPH/TLM, and code-block style 0. It writes reversible QCD style 0 for
`.90` and scalar-expounded style 2 for `.91`. The classic encoder does not
apply MCT: three-component images are stored as RGB, which is a valid profile
and avoids an unnecessary transform. The HTJ2K encoder enables MCT by default
(`employ_color_transform`), so it labels the encoded dataset `YBR_RCT` for
`.201`/`.202` and `YBR_ICT` for `.203` as PS3.5 requires; with the option
disabled it writes RGB.

The decoder accepts multi-tile-part codestreams (parts are concatenated),
multiple quality layers (inclusion, zero-bit-plane and length state persists
across layers, and layer segments are prefixes of one continuous MQ stream),
QCD styles 0/1/2 (style 1 stores the band-0 record and derives every other
band's exponent with the A.6.4 resolution-level reduction, saturating at zero),
COC/QCC overrides (with the one-byte component index mandated for fewer than
257 components), and the LRCP/RLCP/RPCL/PCRL/CPRL progression orders. RPCL/PCRL/CPRL
use precinct index order, which is exact when a resolution has a single
precinct (the DICOM default). When `COD.MCT` is set, the decoder reverses RCT
for reversible streams and ICT for irreversible streams before packing RGB.

POC, PPM, PPT, PLM, RGN, CRG, component subsampling, multi-tile codestreams,
JP2 boxes, and Part 2 extensions are rejected explicitly. A COD `Scod` that
signals SOP or EPH markers is rejected as well, because the packet reader does
not parse start-of-packet/end-of-packet markers. Code-block styles
BYPASS, TERMALL, and PTERM are rejected; RESET, VSC, and SEGSYM are handled.
Per-component COC overrides are accepted only when they keep the COD
decomposition level count and code-block size. Marker lengths, packet bounds,
code-block sizes, bit counts, and allocations are checked; truncated SOD,
missing EOC, duplicate required markers, inconsistent component geometry, and
trailing non-padding bytes fail with `Error::Codec`.

The RESET/VSC/SEGSYM code-block styles and multi-precinct codestreams are
covered by unit round trips; they are not part of the current fo-dicom interop
matrix (which uses style 0 and one precinct per resolution).

## Parameters and metadata

`J2kParams::rate` is a project encoding policy for the target compression
ratio; DICOM and ISO/IEC 15444-1 do not define that field. The classic encoder
emits a single quality layer, so `rate` and `rate_levels` are accepted but do
not change the codestream yet. `allow_mct` is accepted; the classic encoder
stores RGB without MCT, while the HTJ2K encoder applies MCT and relabels the
dataset as described above. `update_photometric_interpretation` is always
applied for three-component output (the adapter exposes RGB).
`encode_signed_as_unsigned` is rejected explicitly rather than silently
changing the sample domain.

The decoded codestream must agree with DICOM geometry. If the codestream uses
RCT/ICT, the adapter exposes RGB. Lossless paths compare samples exactly after
native byte order and planar repacking; lossy paths use bounds tied to the
project quality profile, not ISO or DICOM requirements.

The irreversible path follows OpenJPEG's coefficient convention exactly. The
QCD stores `1/norm` per subband, and both the encoder's quantization step and
the decoder's inverse-quantization step include the subband's 2-D gain
(`2^gain` = 1/2/2/4 for LL/HL/LH/HH, Equation E-4) because that is where the
reference implementations fold it. The synthesis filter itself uses the
standard `1/K` high-pass gain from Annex F.3. OpenJPEG's inverse transform uses
`2/K` instead (`two_invK` in `dwt.c`, a documented historical quirk compensated
by using `R_b = prec` in `tcd.c`); that pair differs from the standard by
exactly the subband gain. Pairing `1/K` synthesis with a gain-scaled step
reproduces OpenJPEG and OpenJPH samples; pairing `1/K` with an unscaled step is
wrong by a factor of two per detail direction, and an OpenJPEG-written `.91`
codestream decodes about 30 grey levels away from OpenJPEG's own output.

A codestream may carry a wider precision than the destination's `BitsStored`:
fo-dicom's OpenJPH encoder writes `BitsAllocated` (16) into SIZ for a 12-bit
dataset. The decoder therefore accepts any codestream precision between
`BitsStored` and `BitsAllocated`, re-centres the samples on the destination's
level shift, and refuses samples that do not fit `BitsStored` instead of
clamping them. Signed data still requires an exact match.

## Verification

- Unit tests cover bit stuffing, marker parsing, geometry, MQ, Tier-1, tag
  trees, pass-count coding, 5/3 and 9/7 transforms, quantization, codestream
  round trips (including custom precincts), and the DICOM frame adapter.
- Facade tests cover 8/16-bit, 12-bit-stored, signed, RGB, planar RGB, and
  multi-frame paths through `PixelData`.
- The registry/transcoder integration test covers `.90` exact transcoding,
  `.91` tolerance, RGB, multi-frame, and malformed-codestream rejection without
  a partial frame.
- An OpenJPEG-written irreversible codestream and the samples that release
  decodes back are embedded in a unit test, so the coefficient convention above
  cannot regress silently (it fails by 114 grey levels without the subband
  gain).
- The OpenJPEG 2.5.4 bidirectional matrix (`node .interop/matrix.js`, git-ignored
  with the downloaded binaries) passes after the correction: `.90` is
  byte-exact in both directions at 8 and 12 bits, an OpenJPEG `.91` decodes
  within `mean 0.002 / max 1` of OpenJPEG's own output at 8 bits (`0.036 / 1` at
  12 bits), and an OpenJPEG decode of a Rust `.91` is within `mean 0.172 / max 2`
  of the Rust decode of the same codestream. The 12-bit cases store 12 bits in
  16-bit words.
- The fo-dicom.Codecs 5.16.7 DICOM-level matrix (`.interop/dicomref`, C#) passes
  in both directions for `.90` and `.91` at 8 and 12 bits: a fo-dicom stream
  decodes exactly (`.90`) or within `max 1` (`.91`), and fo-dicom decodes a Rust
  stream within `max 2`.
- The optional pure-Rust `j2k_tool` example is a developer utility for manual
  codestream inspection; `--stored` separates `BitsStored` from
  `BitsAllocated` for 12-bit-in-16 frames.

## Stages and checks

1. Marker/bit/geometry primitives and malformed-header tests. (done)
2. 5/3, MQ, EBCOT, tag trees, packet assembly, and exact `.90` round trips. (done)
3. 9/7, quantization, multi-layer decoding, and `.91` tolerance tests. (done)
4. DICOM frame/color adapter, multi-frame/padding/planar/signed tests. (done)
5. OpenJPEG bidirectional matrix and the embedded OpenJPEG `.91` fixture. (done;
   the HTJ2K half still needs an OpenJPH or fo-dicom oracle, and broader
   fuzzing remains future work)

The implementation target is pure Rust with no native, FFI, vendored, or
third-party JPEG 2000 runtime dependency. HTJ2K remains in this same crate and
uses the shared contract until its Part 15 block coder is implemented.
