# Classic JPEG 2000 codec design

## Standard and reference

- ISO/IEC 15444-1 / ITU-T T.800, JPEG 2000 core coding system.
- DICOM PS3.5, JPEG 2000 transfer syntaxes and encapsulated pixel data.
- Reference behavior: `fo-dicom.Codecs\Codec\DicomJpeg2000Codec.cs`.
- Pure managed reference: `fo-dicom.PureCodecs\docs\design\jpeg2000-codec-design.md`.

## Registrations

| Type | UID | Coding mode |
| --- | --- | --- |
| `Jpeg2000LosslessCodec` | `1.2.840.10008.1.2.4.90` | reversible 5/3 |
| `Jpeg2000LossyCodec` | `1.2.840.10008.1.2.4.91` | irreversible 9/7 |

Both types implement `radicom::pixel::codec::Codec` and use `J2kParams`.

## Codestream architecture

Shared infrastructure parses and writes SOC/SIZ/COD/COC/QCD/QCC/SOT/SOD/EOC,
tile geometry, components, precincts, packets, and bounded marker lengths. The
classic path then performs level shift, reversible or irreversible wavelet
transforms, quantization, EBCOT Tier-1 MQ coding, and Tier-2 packet assembly.

Classic JPEG 2000 and HTJ2K share geometry and marker parsing only. They do not
share block coding or packet policy in a way that changes either standard.

## DICOM parameters

`J2kParams` maps the PureCodecs contract:

- `irreversible` selects 5/3 or 9/7;
- `rate` and `rate_levels` control lossy allocation;
- `allow_mct` controls multi-component transform use;
- `update_photometric_interpretation` controls metadata updates;
- `encode_signed_as_unsigned` controls signed sample mapping.

Progression order and unsupported options are validated before frame processing.
The adapter handles RGB/YBR normalization, signedness, bits stored versus bits
allocated, and decoded component repacking.

## Supported and rejected codestreams

The first release consumes raw J2K codestreams in DICOM encapsulation. JP2-wrapped
frames, JPEG 2000 Part 2 multi-component syntaxes, JPIP/JPT, unsupported
progression orders, unsupported component subsampling, and unsupported photometric
interpretations fail with managed errors.

## Tests

- Marker, bitstream, tag-tree, MQ, wavelet, quantization, Tier-1, packet, and
  progression-order tests.
- Lossless exact round-trips for 8/16-bit monochrome and RGB layouts.
- Lossy fixed-tolerance tests for supported rate parameters.
- Tile, multi-frame, MCT, signed pixel, and metadata-update tests.
- Invalid codestream and bounds tests.
- Bidirectional public-API interoperability with `fo-dicom.Codecs`.
